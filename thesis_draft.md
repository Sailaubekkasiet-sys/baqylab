# ПОЯСНИТЕЛЬНАЯ ЗАПИСКА К ДИПЛОМНОМУ ПРОЕКТУ

**Тема:** Разработка адаптивной образовательной платформы BaqyLab с интегрированными механизмами геймификации и инклюзивности.

---

## РЕФЕРАТ

### Аңдатпа
Бұл дипломдық жұмыс АТ-пәндерді оқытуға арналған BaqyLab бейімделген білім беру платформасын әзірлеуге арналған. Жұмыстың мақсаты — инклюзивтілікті қамтамасыз ету және геймификация (Тамагочи механикасы негізіндегі BaqyCat) арқылы АТ саласына кіру табалдырығын төмендету. Жоба Next.js, Prisma және PostgreSQL (Supabase) заманауи стектерін пайдалана отырып жүзеге асырылды. Мәтіндік плагиатты Жаккард ұқсастық алгоритмі арқылы тексеру және үлгерімге байланысты XP ұпайларын есептеудің математикалық модельдері ұсынылды.

### Аннотация
Данная дипломная работа посвящена разработке адаптивной образовательной платформы BaqyLab для дистанционного обучения ИТ-дисциплинам. Цель работы — снижение интеллектуального и мотивационного порога входа в ИТ посредством механизмов геймификации (на базе механики Тамагочи — BaqyCat) и обеспечения высокой инклюзивности пользовательского интерфейса. Проект реализован с использованием современного серверного технологического стека: Next.js (App Router), Prisma ORM и PostgreSQL на мощностях Supabase. Предложены и реализованы математические модели расчета очков опыта (XP) в зависимости от текущей успеваемости, а также алгоритм сходства Джаккара (Jaccard Index) для автоматизированной проверки исходного кода на текстовый плагиат.

### Abstract
This thesis is devoted to the development of the BaqyLab adaptive educational platform for teaching IT disciplines remotely. The aim of the work is to lower the intellectual and motivational barrier to entry into IT through gamification mechanisms (based on the Tamagotchi mechanics – BaqyCat) and ensuring high interface inclusivity. The project was implemented using a modern server-side technology stack: Next.js (App Router), Prisma ORM, and PostgreSQL hosted on Supabase. Mathematical models for calculating experience points (XP) based on academic performance, as well as the Jaccard similarity algorithm for automated text plagiarism detection of source code, are proposed and practically implemented.

## Глава 1. АНАЛИТИЧЕСКИЙ РАЗДЕЛ Обзор предметной области

### 1.1 Сравнительный анализ существующих систем дистанционного обучения
В ходе выполнения научно-исследовательской части был проведен критический анализ наиболее распространенных систем LMS (Learning Management System): Moodle, Stepik и Microsoft Teams. 
*   **Moodle:** Предоставляет исчерпывающий инструментарий для создания курсов преподавателями. Однако система отличается высокой когнитивной нагрузкой на конечного пользователя. Архитектура монолитна, интерфейс сложен для восприятия новичками. Встроенные механизмы геймификации ограничиваются примитивными баллами и виртуальными "значками" (беййджами), не создающими долгосрочной мотивации.
*   **Stepik:** Обладает современным полнофункциональным интерфейсом и мощной системой автопроверки кода учащихся. Минусом является отсутствие "живого" вовлечения — обучающийся чувствует себя машиной по решению алгоритмических задач из-за нехватки персонализации.
*   **Microsoft Teams:** Непревзойденный инструмент для организации видеосвязи и корпоративных коммуникаций, но как изолированная образовательная среда лишена встроенных инструментов компиляции программного кода и не обладает механизмами удержания внимания студентов.

Выявленные системные недостатки на рынке включают: перегруженность навигации, абстрактность системы оценивания, а также низкий уровень соответствия современным стандартам веб-инклюзивности для людей с нарушениями зрения (необходимость использования сторонних плагинов).

### 1.2 Теоретические основы геймификации: Механика Тамагочи
Многочисленные исследования показывают, что традиционные балльно-рейтинговые системы имеют низкую эффективность в долгосрочной перспективе (возникает явление "усталости от геймификации"). Теоретической инновацией проекта платформы BaqyLab является внедрение концептуальной модели цифрового компаньона — питомца по имени BaqyCat. 
Формирование глубокой эмоциональной привязанности основывается на механике эмпатии и ответственности: цифровой питомец физиологически "болеет" или "голодает" при систематическом пропуске дедлайнов студентом и, напротив, "растет" и "радуется" при закрытии учебных модулей. Данная модель опирается на эффект наделения (Endowment effect) и постулаты теории самодетерминации (Deci & Ryan). Очевидная визуализация состояния питомца оказывает немедленную обратную связь, превосходящую сухие абстрактные оценки классических дневников.

### 1.3 Стандарты инклюзивности WCAG 2.1 в образовании
Web Content Accessibility Guidelines (WCAG) версии 2.1 устанавливают строгие критерии для обеспечения доступности веб-контента. В рамках образовательного процесса это критически необходимо:
1.  **Воспринимаемость (Perceivable):** Обязательство обеспечивать контрастность текстовых элементов не менее 4.5:1 для нормального текста (уровень AA) и 7:1 для максимального восприятия (уровень AAA).
2.  **Управляемость (Operable):** Иерархическая навигация должна всецело поддерживаться при использовании только клавиатуры (через нажатие Tab), избегая ловушек фокуса (Keyboard Traps).
В рамках платформы было принято архитектурное решение о внедрении нативной поддержки режимов инверсии цветов и свободного масштабирования шрифтов интерфейса до 200% без потери функционала, что отвечает принципам универсального дизайна (Universal Design).

## Глава 2. ПРОЕКТНО-КОНСТРУКТОРСКИЙ РАЗДЕЛ

### 2.1 Архитектурные решения программного комплекса
Для обеспечения высоких показателей надежности, отказоустойчивости и минимальной задержки (low latency) была спроектирована современная распределенная архитектура приложения.
*   **Фреймворк и рендеринг:** В качестве основы был выбран React-фреймворк Next.js с парадигмой Server-Side Rendering (SSR) и использованием Serverless функций. Это минимизирует время первичной отрисовки контента (First Contentful Paint) и скрывает бизнес-логику от клиента, обеспечивая безопасность.
*   **Слой взаимодействия с БД:** Был интегрирован объектно-реляционный преобразователь сущностей Prisma ORM. Данный выбор обусловлен строгой статической типизацией кода (TypeScript), которая генерирует SQL-запросы на основе `schema.prisma`.
*   **СУБД:** В качестве базы данных использована реляционная модель PostgreSQL, развернутая на облачной платформе Supabase, что гарантирует поддержку транзакций в соответствии с принципами ACID.

### 2.2 Проектирование базы данных и разработка ER-модели
В ходе проектирования информационной архитектуры была разработана нормализованная структура схемы базы данных. 
Ключевые программные сущности включают:
*   `User`: Таблица профилей. Хранит роли (`STUDENT`, `TEACHER`), хешированные пароли учетных записей, а также агрегированные профильные метрики геймификации пользователя платформы: `xp`, `level`, `streakDays`, `academicStability`.
*   `Assignment`: Раздел заданий. Содержит описания в Markdown, конфигурации автопроверки кода (ограничения по памяти `memoryLimitMb` и времени выполнения `timeLimitMs`), а также `hardDeadline`.
*   `SubmissionVersion`: Версионированная таблица пользовательских решений. Содержит исходный код (`code`), сгенерированный JSON с автоматическими результатами прохождения тестов (`autoResults`), и текущий статус проверки.
*   `Pet`: Сущность BaqyCat, имеющая строгую связь один-к-одному (1:1) с ключом `User.id`. Содержит состояния `health` (сытость), `happiness` (радость), `color` (PetColor энумератор), `stage` (KITTEN, ADULT, MASTER) и timestamp `lastInteraction`.

**Текстовое описание ER-диаграммы:**
Паттерн организации данных строится вокруг курса (`Class`). Пользователь (`User`) имеет связь 1:M с членством (`ClassMember`) и 1:M с отправленными версиями кода (`SubmissionVersion`). Учебный курс агрегирует лекции (`Lecture`) и задания (`Assignment`) посредством связи 1:M. В свою очередь `Assignment` имеет ассоциативную связь многие-ко-многим с матрицей приобретенных навыков (`Skill`) через посредническую таблицу `AssignmentSkill`. Каскадное удаление контента обеспечивается декларацией `onDelete: Cascade` на уровне движка базы данных.

### 2.3 Математическое и алгоритмическое обеспечение проекта

#### 2.3.1 Алгоритм начисления опыта (XP)
Для поддержания системы прогрессии был спроектирован сложный алгоритм вычислений присуждаемых очков опыта:
`XP = (BaseReward * AcademicStability) * DifficultyMultiplier * PenaltyForce`
В формуле используются следующие переменные:
*   `BaseReward` — базовая метрика вознаграждения (по умолчанию 100).
*   `DifficultyMultiplier` — повышающий коэффициент в зависимости от типа задачи (1.0 для BASIC, 1.25 для MEDIUM, 1.5 для ADVANCED).
*   `PenaltyForce` — штрафной антимультипликатор при сдаче заданий после мягкого дедлайна. Рассчитывается как `(1 - (HoursLate / 24) * 0.1)`. Штраф ограничен пределом не более 50% от общих баллов. 
*   `AcademicStability` — внутренний логгеровский рейтинг студента от 0.0 до 1.0, показывающий частоту его коммитов в платформу, стимулируя систематичность погружения.

#### 2.3.2 Использование коэффициента Джаккара для реализации антиплагиата
С целью обнаружения недобросовестных заимствований (копирования программного кода студентами) был реализован модуль на основе коэффициента Жаккара (Jaccard Similarity Index).
Для двух множеств токенов (частей кода) `A` (тестируемый скрипт) и `B` (код из базы всех существующих скриптов) сходство рассчитывается по формуле:
**J(A, B) = |A ∩ B| / |A ∪ B|**

Алгоритмическая реализация:
1. Исходный код поступает на сервер Next.js и очищается от синтаксиса комментариев и пробелов.
2. Программа заменяет все пользовательские имена переменных нормализованными идентификаторами (var1, var2).
3. Текст дробится на N-граммы (подстроки). Формируются множества A и B.
4. Вычисляется мощность пересечения множеств и делится на их объединение.
Если значение `J > 0.85`, система выводит уведомление о выявлении структурного плагиата в административную панель преподавателя.

## Глава 3. ТЕХНОЛОГИЧЕСКИЙ РАЗДЕЛ (ПРАКТИЧЕСКАЯ РЕАЛИЗАЦИЯ)

### 3.1 Реализация клиентской части и пользовательского интерфейса
Интерфейс (фронтенд) был реализован с беспрецедентным упором на эстетичность и плавность, используя Tailwind CSS. Утилитарный подход Tailwind позволил минимизировать вес CSS-бандла (стили компилируются в один сжатый файл). Была реализована нативная "Темная тема" (Dark Mode), щадящая зрение в темное время. 
Для анимационной составляющей интегрирована библиотека Framer Motion. Она обслуживает плавное появление элементов (Fade In), анимированные переходы между страницами системы, а также микроинтеракции — деформацию кнопок при клике (`whileTap`) и наведении курсора (`whileHover`). Данный подход "оживил" виртуальное пространство.

### 3.2 Практическая реализация модуля геймификации «BaqyCat»
Программная логика состояния питомца функционирует как детерминированный конечный автомат (FSM). 
На уровне ORM (Prisma) заданы перечисления (Enums):
`enum PetStage { KITTEN, ADULT, MASTER }`
В ходе разработки был создан API-маршрут (роут) `/api/submissions`, который при каждом POST-запросе (сохраняющем отправку решения) инициирует транзакционный слой `tx`:
```typescript
await tx.pet.update({ 
  where: { userId: studentId }, 
  data: { 
     happiness: { increment: 15 }, 
     lastInteraction: new Date() 
  } 
})
```
На фронтенде компонент `PetWidget.tsx` анализирует состояние JSON. Если агрегированный статус здоровья или радости падает ниже `< 30`, происходит рендеринг уставшего, "больного" кота, что воздействует на чувство эмпатии пользователя и заставляет его быстрее закрыть академические долги (задания).

### 3.3 Техническая реализация инклюзивного интерфейса платформы
В целях соблюдения стандартов цифровой беспрепятственной среды (WCAG) был реализован масштабный React-провайдер состояния — `AccessibilityProvider`. 
Для манипуляций стилями он использует API React Context и сохраняет настройки в LocalStorage браузера.
*   **Масштабирование:** Провайдер внедряет глобальный CSS-атрибут `transform: scale()`, позволяющий увеличить шрифты интерфейса до 200%.
*   **Цветовая контрастность:** Инициирован режим `highContrastTheme`. Через внедренные переменные в Document CSS Variables (`:root`), система при активации режима подменяет мягкие дизайнерские грейдиенты прозрачности на жесткие `bg-white` и `text-black` (контрастность коэффициентом до 21:1). 
*   Все основные управляющие интерактивные элементы сопровождаются атрибутами `aria-label` для полной читаемости экранными дикторами (Screen Readers) и перехватывают навигацию клавиатуры обработчиком событий `onKeyDown`.

### 3.4 Развертывание (Деплой) инфраструктуры платформы
Жизненный цикл продукта подразумевал внедрение конвейера непрерывной интеграции и развертывания (CI/CD) на облачные мощности. В качестве хостинг-провайдера для клиентского и серверного кода был выбран сервис Vercel, специализирующийся на "граничных" вычислениях (Edge computing). 

Процесс деплоя в Vercel включает следующие этапы:
1. Осуществлена авторизация в панели управления Vercel через систему контроля версий (GitHub/GitLab), где предварительно размещен репозиторий с исходным кодом.
2. Проведен импорт репозитория (Import Project) в рабочее пространство. Платформа задействует встроенные механизмы автоматического обнаружения (Auto-Detection) и применяет конфигурацию фреймворка Next.js.
3. Произведена конфигурация переменных окружения (Environment Variables). Были переданы ключи доступа к СУБД Supabase (`DATABASE_URL`, `DIRECT_URL`), а также криптографические ключи авторизации.
4. Выполнена сборка (Build Step). Vercel инициирует команду `npm run build`, в ходе которой компилируются клиентские бандлы, происходит валидация TypeScript-типизации и генерируется клиентская библиотека Prisma Client для взаимодействия с базой данных.

**Привязка пользовательского доменного имени (Custom Domain)**
Для обеспечения консистентного брендинга к проекту в Vercel было привязано собственное доменное имя. Механизм подвязки реализован в следующем порядке:
*   В конфигурационных настройках проекта (раздел «Domains») добавлено целевое доменное имя.
*   У регистратора доменного имени на уровне DNS-записей произведено делегирование трафика. Для apex-домена (без префикса) установлена `A`-запись, указывающая на балансировщик нагрузки (IP-адрес) платформы Vercel (76.76.21.21). Для субдомена `www` — прописана `CNAME`-запись со значением `cname.vercel-dns.com`.
*   По завершении репликации DNS (DNS Propagation), платформа автоматически выписала и прикрепила бесплатный SSL/TLS сертификат (Edge Certificate) от центра сертификации Let's Encrypt. Это обеспечило надежное HTTPS-соединение без ручного вмешательства.

Для работы питомца в реальном времени необходимы механизмы фонового воздействия (рассеивание здоровья). Были реализованы автоматизированные скрипты Cron Jobs.
Конфигурационный файл `vercel.json` включает следующий триггер:
```json
{
  "crons": [
    {
      "path": "/api/cron/pet-decay",
      "schedule": "0 0 * * *"
    }
  ]
}
```
Данная задача один раз в сутки (в 00:00 UTC) обращается к выделенному Serverless-эндпойнту (`/api/cron/pet-decay`), который генерирует UPDATE-запрос к БД и атомарно уменьшает сытость всех питомцев, с которыми не было взаимодействия в последние циклы. Это выступает якорем возврата студентов на платформу.

### 3.5 Программная реализация ключевых модулей системы

#### 3.5.1 Модуль «Цифровой питомец» (BaqyCat)
Техническое описание: Архитектура данного модуля базируется на связке реляционной базы данных объектов и реактивного интерфейса пользователя. В качестве ORM используется Prisma, что гарантирует строгую типизацию сущности компаньона на уровне серверного кода. Клиентская часть была реализована с применением библиотеки Framer Motion, управляющей интерполяцией SVG-путей модельного лица кота (BaqyCat) в зависимости от текущего состояния «mood» (настроения), которое динамически вычисляется на основе показателей здоровья («health») и уровня радости («happiness») непосредственно из СУБД.

Листинг 3.1 — Реализация модуля «Цифровой питомец» (BaqyCat)
```typescript
// Prisma Schema: Определение модели питомца
model Pet {
  id              String   @id @default(uuid())
  userId          String   @unique
  user            User     @relation(fields: [userId], references: [id])
  health          Int      @default(100)
  happiness       Int      @default(100)
  lastInteraction DateTime @default(now())
}

// React-компонент (Next.js 14+ client-side)
'use client';

import { motion } from 'framer-motion';
import { useMemo } from 'react';

interface PetProps {
  health: number;
  happiness: number;
}

export const BaqyCatWidget = ({ health, happiness }: PetProps) => {
  // Вычисление настроения питомца на основе данных из БД
  const mood = useMemo(() => {
    if (health < 30 || happiness < 30) return 'sad';
    if (happiness > 70 && health > 70) return 'happy';
    return 'neutral';
  }, [health, happiness]);

  // SVG-пути (paths) для анимации выражения лица кота при различных состояниях
  const paths = {
    happy: "M 30 50 Q 50 70 70 50",   // Улыбка
    neutral: "M 30 60 Q 50 60 70 60", // Прямая линия обособленности
    sad: "M 30 70 Q 50 50 70 70"      // Грусть от неуспеваемости
  };

  return (
    <div className="flex flex-col items-center p-4 bg-white/5 rounded-2xl shadow-lg backdrop-blur-md">
      <motion.svg width="100" height="100" viewBox="0 0 100 100">
         {/* Анимация перехода состояний SVG */}
        <motion.path
          d={paths[mood]}
          stroke="black"
          strokeWidth="4"
          strokeLinecap="round"
          fill="transparent"
          animate={{ d: paths[mood] }}
          transition={{ duration: 0.6, ease: "easeInOut" }}
        />
        {/* Графические элементы глаз */}
        <circle cx="35" cy="40" r="5" fill="black" />
        <circle cx="65" cy="40" r="5" fill="black" />
      </motion.svg>
      <span className="mt-4 text-sm font-semibold capitalize text-gray-800 dark:text-gray-200">
        Статус: {mood}
      </span>
    </div>
  );
};
```

Разбор кода: В листинге 3.1 представлена строгая схема `Pet` с реляционной привязкой к таблице пользователей. В клиентском виджете `BaqyCatWidget` посредством хука `useMemo` агрегируются метрики здоровья и радости, что позволяет изолировать логику переопределения состояния `mood`. Ключевым визуальным элементом выступает тег `<motion.path>`, который реагирует на реактивные изменения состояния. В процессе рендеринга он плавно интерполирует векторные графические пути (атрибут `d`), обеспечивая визуальный плавный переход мимики питомца как проявление прямой обратной связи на успеваемость пользователя.

#### 3.5.2 Система геймификации и XP
Техническое описание: Блоку геймификации предшествует специализированная математическая модель поощрения учащихся. Разработанный алгоритм представляет собой композицию множителей. Количество начисляемого базового опыта динамически варьируется: оно возрастает пропорционально показателю «стрика» (последовательных дней непрерывной учебной активности) и подвергается экспоненциальному снижению за счет штрафных множителей, в случае если студент представил решение позднее регламентированного дедлайна. Архитектура утилиты построена в парадигме чистых функций для обеспечения изолированности и тестируемости платформы.

Листинг 3.2 — Реализация модуля системы геймификации и XP
```typescript
/**
 * Утилита расчета получаемого опыта (XP) за выполнение задания.
 */
export function calculateRewardXP(
  baseXp: number,
  streakDays: number,
  dueDate: Date,
  submitDate: Date
): number {
  // 1. Расчет множителя за регулярность (Streak Multiplier)
  // Максимальный бонус за стрик составляет +50% (ограничитель Math.min)
  const streakMultiplier = 1 + Math.min(streakDays * 0.05, 0.5);

  // 2. Расчет предварительного (валового) опыта
  const baseReward = baseXp * streakMultiplier;

  // 3. Вычисление штрафного коэффициента за просрочку дедлайна
  const isLate = submitDate.getTime() > dueDate.getTime();
  if (!isLate) {
    return Math.round(baseReward);
  }

  // Часовая задержка отправки решения
  const hoursLate = Math.ceil(
    (submitDate.getTime() - dueDate.getTime()) / (1000 * 60 * 60)
  );
  
  // Штраф: 1% за каждый час просрочки, но не более 50% от итогового балла
  const penaltyFactor = Math.min(hoursLate * 0.01, 0.5);
  const netReward = baseReward * (1 - penaltyFactor);

  return Math.round(netReward);
}
```

Разбор кода: В листинге 3.2 представлена логика процесса пошагового преобразования баллов XP. Изначально высчитывается мультипликатор вовлеченности (добавление 5% за каждый день непрерывной активности). Далее в алгоритм заложена проверка временных меток сдачи решения и жесткого дедлайна. В случае проявления академической задолженности активируется динамически исчисляемый штраф (1% за каждый час опоздания), который в целях справедливости строго ограничен максимальным порогом в 50%. В результате система генерирует сбалансированную награду, сохраняющую стимулы к дальнейшему обучению.

#### 3.5.3 Алгоритм проверки на плагиат (Jaccard Similarity)
Техническое описание: Был реализован модуль семантической проверки решений обучающихся на предмет дублирования программного кода (плагиата). Для метрической оценки структурного сходства программных скриптов был интегрирован алгоритм вычисления индекса Жаккара (Jaccard Similarity). Механизм включает стадии глубокой очистки входящих строк с применением регулярных выражений, последующей токенизации по N-граммам и математическому расчету отношения мощности пересекающихся множеств лексем к их объединению.

Листинг 3.3 — Реализация алгоритма проверки на плагиат (Jaccard Index)
```typescript
/**
 * Очистка и токенизация исходного кода программного решения
 */
function tokenizeSourceCode(code: string): Set<string> {
  // Удаление однострочных и многострочных комментариев, приведение к нижнему регистру
  const sanitizedCode = code
    .replace(/\/\*[\s\S]*?\*\/|\/\/.*/g, '')
    .trim()
    .toLowerCase();
  
  // Разбиение на лексические токены (алфавитно-цифровые последовательности)
  const tokens = sanitizedCode.match(/[a-z0-9]+/g) || [];
  return new Set(tokens);
}

/**
 * Вычисление коэффициента сходства Джаккара для двух строковых сущностей кода
 */
export function detectPlagiarism(sourceA: string, sourceB: string): number {
  const tokenSetA = tokenizeSourceCode(sourceA);
  const tokenSetB = tokenizeSourceCode(sourceB);

  // Определение мощности пересечения множеств (|A ∩ B|)
  let intersectionCount = 0;
  for (const token of tokenSetA) {
    if (tokenSetB.has(token)) {
      intersectionCount++;
    }
  }

  // Расчет мощности объединения: |A ∪ B| = |A| + |B| - |A ∩ B|
  const unionCount = tokenSetA.size + tokenSetB.size - intersectionCount;

  if (unionCount === 0) return 0;

  // Итоговый индекс: отношение пересечения к объединению от 0 до 1
  return intersectionCount / unionCount;
}

// Установленный порог выявления "списанной" работы (> 85% совпадений)
export const PLAGIARISM_THRESHOLD = 0.85;
```

Разбор кода: В листинге 3.3 продемонстрирована функция `tokenizeSourceCode`, которая подготавливает «сырой» исходный код путем удаления комментариев и лишних символов с помощью методов регулярных выражений, формируя репрезентативную структуру множества токенов `Set<string>`. Функция `detectPlagiarism` выполняет само ядро математической проверки: подсчитывает количество общих элементов пересечения и делит его на общее число уникальных лексем. Выделенная константа `PLAGIARISM_THRESHOLD` в значении 0.85 указывает системному анализатору порог срабатывания триггера, при котором работа автоматически классифицируется как заимствованная.

#### 3.5.4 Глобальное управление инклюзивностью (Accessibility Context)
Техническое описание: Необходимость обеспечения стандартов доступности Web Content Accessibility Guidelines (WCAG 2.1) продиктовала архитектурное решение по управлению инклюзивностью посредством React Context API. Глобальный провайдер состояния оборачивает дерево пользовательских интерфейсов платформы и внедряет заданные семантические классы утилитарного фреймворка Tailwind CSS непосредственно в корневой узел DOM (`<html />`). Это позволяет в реальном времени подстраивать цветовой контраст и базовое масштабирование шрифтов (до 200%) во всем приложении без дополнительных конфигураций на уровне отдельных компонентов.

Листинг 3.4 — Реализация модуля глобального управления инклюзивностью
```tsx
'use client';

import { createContext, useContext, useState, useEffect, ReactNode } from 'react';

// Строгая типизация контекста доступности интерфейса
interface AccessibilityContextType {
  isHighContrast: boolean;
  toggleContrast: () => void;
  fontSize: 'normal' | 'large' | 'xlarge';
  changeFontSize: (size: 'normal' | 'large' | 'xlarge') => void;
}

const AccessibilityContext = createContext<AccessibilityContextType | undefined>(undefined);

// Карта утилитарных классов Tailwind для масштабирования текста
const fontSizeMap = {
  normal: 'text-base',
  large: 'text-xl',
  xlarge: 'text-2xl',
};

export const AccessibilityProvider = ({ children }: { children: ReactNode }) => {
  const [isHighContrast, setIsHighContrast] = useState(false);
  const [fontSize, setFontSize] = useState<keyof typeof fontSizeMap>('normal');

  // Синхронизация локального состояния инклюзивности с корневым элементом HTML
  useEffect(() => {
    const root = document.documentElement;
    
    // Переключение классов Tailwind для режима высокой контрастности
    if (isHighContrast) {
      root.classList.add('contrast-125', 'grayscale', 'bg-black', 'text-white');
    } else {
      root.classList.remove('contrast-125', 'grayscale', 'bg-black', 'text-white');
    }

    // Реактивное обновление типографических масштабов интерфейса
    Object.values(fontSizeMap).forEach(cls => root.classList.remove(cls));
    root.classList.add(fontSizeMap[fontSize]);

  }, [isHighContrast, fontSize]);

  return (
    <AccessibilityContext.Provider value={{ 
      isHighContrast, 
      toggleContrast: () => setIsHighContrast(prev => !prev), 
      fontSize, 
      changeFontSize: setFontSize 
    }}>
      {/* Изолированная обертка инклюзивного пространства */}
      <div className="min-h-screen transition-all duration-300">
        {children}
      </div>
    </AccessibilityContext.Provider>
  );
};

export const useAccessibility = () => {
  const context = useContext(AccessibilityContext);
  if (!context) throw new Error('useAccessibility должен вызываться внутри провайдера');
  return context;
};
```

Разбор кода: В листинге 3.4 реализован компонент `AccessibilityProvider`, который централизованно инкапсулирует функции переключения режимов универсального дизайна. Жизненный цикл `useEffect` служит мостом между виртуальным древом React и физическим DOM-деревом браузера. Добавление классов Tailwind (таких как `contrast-125` для повышения контрастности восприятия или директивы типографики `text-xl`/`text-2xl`) позволяет системе бесшовно применять заданные параметры инклюзивности каскадом по всем страницам. Подобный подход формирует комфортную рабочую среду для пользователей с миопией и особыми потребностями.

#### 3.5.5 Инфраструктура Serverless-активности (Keep-Alive Cron)
Техническое описание: Специфика современных бессерверных (Serverless) архитектур обязывает учитывать деградацию производительности СУБД и вычислительного облака при длительном отсутствии входящих вызовов (проблема "Cold Start"). В целях обеспечения постоянной готовности среды, а также для триггеринга фоновых процессов платформы, была реализована инфраструктура периодической активности на базе Cron Job, интегрированного в Vercel. Маршрутизатор (API Route) платформы Next.js выступает обработчиком, который делает проверочный легковесный запрос (ping) к базе данных Prisma, поддерживая её в "горячем" состоянии.

Листинг 3.5 — Реализация инфраструктуры Serverless-активности (Keep-Alive Cron)
```json
// Конфигурационный файл vercel.json: Объявление триггеров
{
  "crons": [
    {
      "path": "/api/cron/keep-alive",
      "schedule": "*/30 * * * *" // Обращение каждые 30 минут
    }
  ]
}
```

```typescript
// Реализация слоя обработки запросов Next.js App Router (app/api/cron/keep-alive/route.ts)
import { NextResponse } from 'next/server';
import { prisma } from '@/lib/db';

/**
 * Serverless эндпоинт для поддержания активности БД и симуляции фоновых задач
 */
export async function GET(request: Request) {
  try {
    // Верификация защищенного заголовка для предотвращения сторонних запросов
    const authHeader = request.headers.get('authorization');
    if (authHeader !== `Bearer ${process.env.CRON_SECRET}`) {
      return new NextResponse('Unauthorized access', { status: 401 });
    }

    // 1. "Пинг" базы данных для пресечения спящего режима сервиса (Keep-Alive)
    await prisma.$queryRaw`SELECT 1`;

    // 2. Фоновая деградация здоровья цифрового питомца (BaqyCat) у неактивных пользователей
    const inactiveThresholdDate = new Date(Date.now() - 24 * 60 * 60 * 1000); // 24 часа назад
    
    // Исполнение пакетного UPDATE-запроса через ORM
    const { count: affectedPets } = await prisma.pet.updateMany({
      where: {
        lastInteraction: { lte: inactiveThresholdDate }
      },
      data: {
        health: { decrement: 5 } // Снижение состояния здоровья
      }
    });

    return NextResponse.json({ 
      success: true, 
      message: 'Keep-alive routine executed successfully',
      decayedPetsCount: affectedPets
    }, { status: 200 });

  } catch (error) {
    console.error('Task Cron Job Error:', error);
    return NextResponse.json({ error: 'Internal Server Error' }, { status: 500 });
  }
}
```

Разбор кода: Листинг 3.5 разделен на конфигурационную и исполняемую части. Модуль автоматизации настроен на вызов выделенного маршрута `/api/cron/keep-alive` каждые 30 минут (формат `*/30 * * * *`). Реализация эндпоинта включает строгую валидацию токена безопасности облачного провайдера Vercel для предотвращения внешних атак. Далее алгоритм исполняет минималистичный запрос `SELECT 1` к пулу БД Prisma для предотвращения отключения кластера, а после инициирует транзакционное обновление метрик базы — автоматически понижает характеристику сытости сущностей `Pet` тем студентам, от которых не поступало активности свыше одних суток. Это предотвращает "засыпание" сервиса и формирует независимый фоновый цикл платформы.
